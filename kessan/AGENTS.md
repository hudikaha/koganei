# kessan 引継ぎ

## 目的と対象

- 小金井市令和7年度決算を、円グラフ、検索、原本ページ、個別事業から閲覧できる静的ページとして生成する。
- 生成コードは `build.rb`、公開先は `https://fujikawa.org/koganei/kessan/`。
- 下水道会計は対象外。
- PDF、抽出データ、生成した `index.html` と `data.json` は Git 管理しない。再生成できるコードと手順だけを管理する。

## 原本の構造と用語

- 原本中央欄の正式な階層は `款 → 項 → 目 → 節`。
- 原本右端は「備考」欄で、`事業 → 番号付き内訳 → 個別支出` という区別がある。
- 備考欄の番号付き内訳は節番号・名称と対応するが、原本で「節」と命名されてはいない。画面では必ず「内訳」と呼ぶ。
- 備考欄側のデータを `事業 → 節` と説明しない。
- 「事業を円グラフ化」を有効にした場合だけ、正式な節の下に対応する複数事業を集計し、`目 → 節 → 事業` の追加表示を行う。

## 画面仕様

- 「事業を円グラフ化」はラジオボタンではなく、一つのチェックボックス。
- チェック時は、選択済みの節、または複数事業を最も多く含む節を開き、次の独立した円グラフまで表示・スクロールする。
- 円グラフの扇と凡例、一覧の事業をクリックした場合は、必ずURLも選択状態に合わせて更新する。
- URLは `page`、`jigyo`、必要に応じて `section` と `view=business` を使い、再読込とブラウザの戻る操作で状態を復元する。
- `page` と `jigyo` が矛盾した場合は `page` を優先し、`jigyo` を補正する。ただし個別事業URLから開いた場合は、その事業を直接開く。
- `jigyo` は `ippan-4`、`ippan-4-1`、`ippan-4-1-3`、個別事業を含む形式を受け付ける。会計略称は `ippan`、`kokuho`、`kaigo`、`koki`。
- 正常な一致は通常状態なので、「一致しています」などの成功文を表示しない。不一致だけを目立つ警告として表示する。
- 詳細な説明は備考欄から抽出した個別支出を表示する。原本を確認せず、名称や階層を推測で追加しない。

## 作業手順

- 個別コマンドを会話から組み直さず、原則としてこのディレクトリの `Makefile` を使う。
- `make check`: 再生成、Ruby・JSON・JavaScript・必須UIの検査。
- `make publish`: clean、生成・検査、公開転送、公開ページ確認。
- `make release MSG="説明"`: publish後、対象コードをcommit/pushし、`YYYYMMDDHHMM` のタグを作ってpushする。
- 転送内容だけ確認する場合は `make deploy-dry-run`。
- UI変更では、生成物にコードが含まれるだけで完了としない。可能なら対象URLでクリック後の状態とURL変化も確認する。

## 変更時の注意

- 長い会話中の暫定案より、このファイルに記録された確定仕様を優先する。
- ユーザーの訂正が重なって意味が曖昧になった場合は、原本の列見出しと通常の画面動作を確認してから変更する。
- 新たに確定した再利用可能な仕様や手順は、セッション終了前にこのファイルまたは `Makefile` に反映する。
